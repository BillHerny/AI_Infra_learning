cmake_minimum_required(VERSION 3.20)
project(cuda_basic LANGUAGES CXX CUDA)

set(CMAKE_CUDA_STANDARD 17)
set(CMAKE_CUDA_STANDARD_REQUIRED ON)
set(CMAKE_CUDA_ARCHITECTURES 89)

# 各子目录的可执行产物统一输出到 build/ 根，运行路径恒为 ./build/<target>
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)

add_subdirectory(hello_cuda)
add_subdirectory(vector_add)

#[===[
========================================================================
本文件：cuda_basic 工程的"顶层" CMakeLists.txt
========================================================================

  这个文件把 cuda_basic/ 定义成一个"CMake 工程"，并向下组织各个练习：
  每个练习占一个子目录，各自带一个只描述自己目标的 CMakeLists.txt。
  约定：工程级设置写在本文件，目标级命令写在子目录文件里。

------------------------------------------------------------------------
【第 1 行】cmake_minimum_required(VERSION 3.20)
------------------------------------------------------------------------

  · 声明本工程所需的 CMake 最低版本为 3.20。
  · 版本号不仅决定"能否构建"，还会切换 CMake 的策略（Policy）默认
    行为，例如 CUDA 作为一等语言（LANGUAGES CUDA）、较新的 CUDA
    架构检测逻辑等都依赖较新版本，写低了可能行为不一致。
  · 若本机 CMake 低于 3.20，会在配置阶段直接报错终止，而不是产生
    难以排查的构建错误——这是一种"尽早失败"的保护。

------------------------------------------------------------------------
【第 2 行】project(cuda_basic LANGUAGES CXX CUDA)
------------------------------------------------------------------------

  · cuda_basic：工程名，会写入 ${PROJECT_NAME} 等变量。
  · LANGUAGES CXX CUDA：启用两种源码语言——
      - CXX  → 由 C++ 编译器（g++/clang++）编译 .cpp 文件；
      - CUDA → 由 NVIDIA 的 nvcc 驱动编译 .cu 文件，主机端代码交给
               底层 C++ 编译器，设备端代码编译成 GPU 可执行的 PTX/cubin。
  · CMake ≥ 3.8 原生支持 CUDA 语言，因此无需 find_package(CUDA)，
    并会自动定位 nvcc、自动注入 cudart 运行时库。

------------------------------------------------------------------------
【第 3 行】set(CMAKE_CUDA_STANDARD 17)
------------------------------------------------------------------------

  · 指定编译 .cu 文件所使用的 C++ 标准为 C++17。
  · 这是"目录级默认值"：作用于本目录，并向下传递给所有通过
    add_subdirectory 纳入的子目录，子目录无需重复设置。
  · 选 17 的原因：结构化绑定、if constexpr、std::optional 等特性
    既现代，又被主流 CUDA 工具链良好支持。

------------------------------------------------------------------------
【第 4 行】set(CMAKE_CUDA_STANDARD_REQUIRED ON)
------------------------------------------------------------------------

  · 强制要求编译器必须支持第 3 行指定的标准。
  · 若为 OFF（默认），当 nvcc 不支持 C++17 时 CMake 会"静默降级"
    到较低标准，导致 C++17 代码编译失败且原因隐蔽。
  · 为 ON 时，在配置/编译阶段就能得到明确报错，便于定位环境问题。

------------------------------------------------------------------------
【第 5 行】set(CMAKE_CUDA_ARCHITECTURES 89)
------------------------------------------------------------------------

  · 指定为哪一代 GPU 生成代码。89 对应 Ada Lovelace 架构
    （RTX 40 系，含本机的 RTX 4060 Laptop，compute capability 8.9）。
  · 不写此行时，CMake 可能按默认值生成（本工程早期日志里出现过
    sm_52），结果是白编一堆用不上的旧架构代码，既慢又臃肿。
  · 同样属于目录级默认值，会向下传递给子目录。

------------------------------------------------------------------------
【第 6 行】set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR})
------------------------------------------------------------------------

  · 让所有子目录产出的可执行文件都落到 build/ 根目录下。
  · 不加这行的话：子目录 hello_cuda 的目标会被输出到
    build/hello_cuda/hello_cuda，运行路径随目录层级越变越长。
  · 加上后，运行命令恒为 ./build/<target>，简单直观
    （${CMAKE_BINARY_DIR} 就是 -B 指定的那个构建目录）。

------------------------------------------------------------------------
【第 7 行】add_subdirectory(hello_cuda)
------------------------------------------------------------------------

  · 把 hello_cuda/ 子目录纳入构建：CMake 会进入该目录，并执行它
    自己的 CMakeLists.txt。
  · 子目录文件遵循"只声明目标"的约定：不写 cmake_minimum_required、
    不写 project、不写全局 set(...)，只写 add_executable 等目标级命令。
  · 想新增一个练习（例如 vector_add），只需四步：
      1) 建目录 cuda_basic/vector_add/；
      2) 把源码 vector_add.cu 放进去；
      3) 在 vector_add/ 里写一个只含 add_executable 的 CMakeLists.txt；
      4) 在本文件末尾追加一行 add_subdirectory(vector_add)。
  · 本文件与子目录文件的分工，就是"工程级 vs 目标级"。

========================================================================
补充：构建与运行（在本工程根目录 cuda_basic/ 下执行）
========================================================================

  标准流程分三个阶段：① 配置 → ② 构建 → ③ 运行。

  【① 配置】cmake -S . -B build
    · -S .     ：源码目录 = 当前目录，即去找这里的顶层 CMakeLists.txt。
    · -B build ：构建目录 = ./build，不存在会自动创建。
    · 这一步只生成构建系统（Makefile）与缓存，一个源文件都不编译；
      重复执行是安全的，配置没变时直接跳过。

  【② 构建】cmake --build build
    · 编译该工程下的"所有目标"（当前是 hello_cuda）。
    · 只想编某一个目标：cmake --build build --target hello_cuda
    · 与生成器无关（Makefile / Ninja / Visual Studio 都不用改命令）；
      追加 -j 可并行编译，例如 cmake --build build -j。

  【③ 运行】./build/hello_cuda
    · 当前目录默认不在 PATH 搜索路径里，必须显式加 "./" 前缀。
    · 由于第 6 行统一了输出目录，运行路径恒为 ./build/<target>。

  改完代码后的日常循环：② 构建 → ③ 运行（① 通常只需执行一次）。

========================================================================
补充：传统写法 vs 现代写法
========================================================================

  同一件事有两套流传的写法，功能等价，只是风格不同：

      传统写法（先手工进入 build 目录）      现代写法（在工程根目录）
      ----------------------------------   ----------------------------------
      mkdir build && cd build              cmake -S . -B build
      cmake ..                             cmake --build build
      make                                 ./build/hello_cuda
      ./hello_cuda

  · 差别一：命令在哪个目录执行
      - 传统写法必须先 cd 进 build/，所以源码路径写成 ".."，运行则是
        "./hello_cuda"（人已在 build/ 里）。
      - 现代写法直接在工程根目录执行，源码目录 / 构建目录 / 当前目录
        都用参数显式写出，不必来回 cd；且 -B build 会自动建目录。

  · 差别二：make 与 cmake --build 的通用性
      - make 直接调用当前目录的 Makefile，只有生成器是 Makefile 时
        才成立；换成 Ninja / VS / Xcode 立刻失效。
      - cmake --build 是与生成器无关的统一入口，更可移植，也是官方
        推荐的现代写法。

  · 等价关系（功能完全一致）：
        cmake ..  +  make   ≈   在 build/ 里执行
                                 cmake -S .. -B .  +  cmake --build .

========================================================================
补充：工程 / 目标 / 目录，以及 CMake 到底会编译哪些文件
========================================================================

  · CMake 只编译"点名的"文件：只有当源文件被明确写进
    add_executable / add_library 的列表时才会被编译，它不会自动
    扫描目录。没被列出的 .cu 永远只是一个躺着的文本文件。
  · 三个概念别混：
      工程（project）＝ 一个顶层 CMakeLists.txt，即本目录；
      目标（target） ＝ 工程里产出的东西，如 hello_cuda；
      目录（folder） ＝ 只是放文件的地方，本身不决定编译什么。
  · 由本工程的组织方式可见：cuda_basic/ 是"工程"，下面的
    hello_cuda/ 只是"子目录"，其中的可执行文件才是"目标"。
  · cmake 与 cmake --build 的区别：
      cmake -S . -B build            → 只生成构建系统，不编译代码；
      cmake --build build            → 编译所有目标；
      cmake --build build --target X → 只编译目标 X。

========================================================================
补充：关于本注释块语法
========================================================================

  · 本文件使用的是 CMake 的"括号块注释"：以方块括号开始、以方块括号
    结束，中间内容原样保留、无需逐行加 "#"，适合放说明文档。
  · 关键陷阱：普通括号块注释在遇到第一组结束定界符时就会结束，且
    不支持嵌套；因此正文里不能直接书写那组结束字符。否则注释会提前
    闭合，其后的文字会被当成 CMake 命令解析并报错：
    "Expected a command name, got quoted argument ..."。
  · 解决办法：改用"带等号"的定界符——在开头的方括号之间插入若干
    等号（本文件用的是三个），结尾用相同数量的等号对称闭合。
    改为该形式后，正文即可安全地书写结束字符而不提前闭合。
